# 评测报告与口径

> 所有数字都可用 `python scripts/run_eval.py` 复现；原始结果见 `reports/rag-eval.{json,md}`。
> 本文解释**这些数字意味着什么、不意味着什么**。

## 1. 评测集

`data/eval_set.json`，共 26 条：

| 类型 | 条数 | 来源 | 判定 |
|---|---|---|---|
| 可答 | 20 | 12 篇语料（8 篇政策 + 4 篇商品），覆盖退货、物流、支付、保修、关税、会员、隐私、投诉 | 必须答对且带正确引用 |
| 不可答 | 6 | 知识库**确实没有**的信息：门店、双十一、加拿大清关、以旧换新、加密货币、学生优惠 | 必须拒答转人工 |

每条都标注了 `expected_doc_ids`（判定 hit@k / 引用准确率）和 `expected_key_points`（判定要点覆盖）。
不可答用例的选取原则是：**问题里有明确实体，而该实体在 12 篇语料中从未出现**——这样"答不了"才是可核实的事实，而不是主观判断。

## 2. 指标定义

| 指标 | 定义 | 为什么这样定 |
|---|---|---|
| hit@k | 可答问题中，期望文档出现在 top-k 召回结果的比例 | 衡量检索是否"找得到" |
| MRR | 期望文档首次出现的排名的倒数均值 | 衡量排得"够不够前" |
| 拒答正确率 | `no_answer == (not answerable)` 的比例 | 误答与误拒同权，防止只优化一边 |
| 引用准确率 | 引用文档中属于期望文档的比例 | 防"引用了但引错" |
| 忠实度 | 答案字符 3-gram 被其引用片段覆盖的比例 | 无法用同义改写伪造支撑 |
| 要点覆盖率 | 期望要点字符串出现在答案中的比例 | 近似"答到点子上" |

## 3. 标定过程（先看分布，再定阈值）

`python scripts/calibrate.py` 对 26 条逐一打印检索最高分与可答性覆盖率：

| 组 | 检索最高分 | 可答性覆盖 |
|---|---|---|
| 可答（20 条） | 0.3509 ~ 0.5898 | 0.383 ~ 1.000 |
| 不可答（6 条） | 0.1752 ~ 0.3936 | 0.000 ~ 0.625 |

**结论一：单靠相似度阈值不可分。** 可答最低 0.3509，不可答最高 0.3936，区间重叠 0.04。
原因很具体：U03"加拿大清关要什么资料"确实命中《跨境关税与清关说明》，主题高度相关，只是答案不在里面——这是语义相近但不可答的典型。

**结论二：需要第二个信号。** 采用"问题里的实体是否出现在证据里"作为可答性判据，IDF 加权（防止"多少""可以"这类高频词稀释），OOV 词按最高权重惩罚。

**阈值选择：**

| 参数 | 取值 | 依据 |
|---|---|---|
| 检索阈值 `XM_RAG_SCORE_THRESHOLD` | 0.18 | 低于可答组最低分（0.3509）留足余量，同时能挡掉纯跑题问题 |
| 可答性阈值 `XM_RAG_ANSWERABILITY_THRESHOLD` | 0.30 | 在可答组最低覆盖（0.383）之下，宁可漏判也不错拒 |
| 分块大小 | 260 字 / 15% 重叠 | 对比 200/240/280/320/420：260 时 24 块、hit@5 满分且引用粒度更细 |
| 融合权重 α | 0.6 | 向量主导语义召回，BM25 补型号/SKU 字面命中 |

分块扫描（同样 26 条，仅换 chunk_size）：

| chunk_size | 知识块数 | hit@5 |
|---|---|---|
| 200 | 27 | 20/20 |
| 240 | 24 | 20/20 |
| 260 | 24 | 20/20 |
| 320 | 24 | 20/20 |
| 420 | 13 | 20/20 |

选 260 而不是更小：块太小会把一条政策拆成碎片，引用原文读起来割裂；260 是"检索精度"和"引用可读性"的折中。

## 4. 最终结果（离线模式）

```
cases=26
hit@5=1.0000   MRR=1.0000
refusal_accuracy=0.9231
citation_precision=1.0000
faithfulness=0.9971
key_point_coverage=0.8500
avg_latency_ms=2.73
```

- **检索满分**：20 条可答问题的期望文档全部进入前 5，且 17 条排第 1。
- **引用零错误**：所有引用都指向期望文档，没有"引用越界"或引错文档。
- **拒答 24/26**：4 条不可答被正确拒答；2 条被误答（见下）。
- **要点覆盖 0.85**：17 条完全命中，3 条未命中。

## 5. 失败用例逐条分析

| 用例 | 现象 | 根因 | 改进方向 |
|---|---|---|---|
| U03 加拿大清关 | 被回答（引用 AP-005） | "加拿大"缺失，但"清关/资料/需要"覆盖度高，覆盖率 0.567 > 0.30 | 对**高频实体的缺失**零容忍：任一高 IDF 词缺失即拒答；或换 NLI/LLM judge |
| U05 加密货币付款 | 被回答（引用 AP-003） | 同上，覆盖率 0.625 | 同上 |
| E13 能否带上飞机 | 答案未含 `74Wh` | 语料写的是"可随身携带登机"，与"飞机"无字面重叠；离线生成器选句失败 | 真实模型可处理同义改写；离线模式记录为已知局限 |
| E16 删除数据多久 | 答案未含 `30 天` | 同上：选中"可请求删除"而非"30 天内完成" | 生成端更强的上下文利用 |
| E19 充满电用几天 | 答案未含 `14 天` | 同上：选中"充满约 90 分钟" | 同上 |

> 注意最后三行都是**离线夹具的选句上限**，不是检索或引用链路的问题：检索正确、引用正确、忠实度满分，只是没挑到最有信息量的那句。

## 6. 这个评测**不能**证明什么

1. **不能证明模型质量。** 离线模式的生成器是确定性抽取式夹具，忠实度 0.997 是"照抄引用"的结构性结果，不是模型不幻觉。
2. **不能外推到真实用户分布。** 26 条是自建集，覆盖了业务主路径，但没覆盖多轮指代、长尾口语、混合意图。
3. **不能代表线上延迟。** 2.73 ms 是无网络的本地循环；真实链路还要加 LLM 首 token + 网络往返。

要得到可对外的质量结论，必须：切 `XM_LLM_PROVIDER=openai`，用同一套脚本重跑，并人工抽检 20 条答案。命令不变，只换环境变量。

## 7. 复现

```bash
# 分布与阈值依据
python scripts/calibrate.py

# 完整评测（写 reports/rag-eval.json + .md）
python scripts/run_eval.py

# 压测（写 reports/load-test.json）
python scripts/load_test.py --requests 300 --concurrency 20
```

CI 中的 `Offline RAG evaluation (quality gate)` 步骤会跑同一脚本：hit@5 或拒答正确率低于 0.9 时以非零码退出。
