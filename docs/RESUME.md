## 0. 三条纪律（先看这个）

1. **写"个人项目"，不要写成公司项目。** 面试官一问"团队多大、上线给谁用"就会露。正确写法：`个人项目 / 独立完成`。
2. **每个数字都能当场复现。** 本文所有指标都来自仓库脚本（`pytest`、`scripts/run_eval.py`、`scripts/load_test.py`）。被追问时直接说命令，比背数字可信十倍。
3. **主动说清 mock 边界。** "离线模式用确定性夹具验证链路，质量结论要接真模型重测"——这句话会显著提升可信度，而不是减分。

## 2. 简历条目 · AI 应用开发岗（推荐，5 条）

- **从 0 设计并实现**跨境电商多智能体平台：FastAPI 提供 12 个 REST 端点，LangGraph 编排 `路由 → 规划 → 检索 → 领域专精 → 自检 → 人工确认` 六阶段流程，覆盖客服/文案/翻译/选品四类任务；**145 条自动化测试全部通过、行覆盖率 92%**（单元 + HTTP 集成 + 供应商降级）。
- **设计可溯源 RAG 链路**：章节感知分块（260 字 / 15% 重叠）+ BM25 与哈希向量混合检索 + 确定性重排；引用由**系统回填而非模型生成**，编号越界自动剔除；26 条评测集上 **hit@5 = 1.0、引用准确率 = 1.0、忠实度 = 0.997**。
- **构建双重拒答机制**：检索分数阈值 + 基于 IDF 加权的**可答性门禁**（问题实体未出现在证据中即拒答），在生成前拦截不可答问题，**拒答正确率 0.923**，且拒答路径不产生模型调用。
- **实现人工在环（HITL）审批**：对外发布类任务（文案/选品）在 `awaiting_approval` 暂停并持久化完整状态快照，审批后从快照恢复而非重跑链路；支持通过/驳回，全流程审计。
- **补齐生产级工程能力**：API Key→租户隔离、令牌桶限流、`Idempotency-Key` 幂等重放、模型重试/熔断/降级、结构化日志 + 全链路 Trace + Prometheus 指标；离线单请求 **p50 8.9 ms**，20 并发 300 请求 **116.7 rps / p95 213 ms / 0 错误**。

## 4. 简历条目 · RAG / 算法岗（4 条）

- 构建 12 篇 / 24 块跨境电商知识库与 26 条评测集（20 可答 + 6 **实体缺失型不可答**），定义 hit@k、MRR、拒答正确率、引用准确率、字符 3-gram 忠实度、要点覆盖率六项指标。
- 用 `scripts/calibrate.py` 先打印分数分布再定阈值：发现可答组最低 0.3509 与不可答组最高 0.3936 **区间重叠**，据此论证"单一相似度阈值不可分"，引入可答性门禁。
- 对比 200/240/260/320/420 五种分块粒度，依据召回与引用可读性选择 260 字；用饱和映射 `bm25/(bm25+K)` 替代 min-max 归一化，修复"最高分恒为 1.0 导致阈值失效"的缺陷。
- 如实报告失败用例（"加拿大清关""加密货币付款"两条 near-miss 误答），并给出可执行的改进路径（高 IDF 实体零容忍 / NLI judge）。

## 5. 三分钟口述版（面试开场，照这个讲）

> 这是我独立做的一个跨境电商多智能体平台，解决的问题是：跨境卖家每天要做客服、文案、翻译、选品四件事，它们共用同一份商品和政策知识，但输出形态完全不同。
>
> 技术上分三层。最上面是 FastAPI，12 个端点；中间是 LangGraph 编排的六个阶段：意图路由、规划、检索、领域专精、自检、人工确认；下面是 RAG 和模型抽象层。
>
> 有两个设计我觉得比较关键。
>
> 第一个是**引用不让模型写**。模型只输出【1】这种编号，来源的文档名、小节、分数全由系统回填，编号越界直接剔除。这样"可溯源"就变成可校验的性质，而不是提示词里的请求。配套还有双重拒答：检索分数不够直接拒，回答了但没有引用也拒。
>
> 第二个是**阈值是量出来的**。我先写了个脚本把 26 条评测题的检索分数打出来，发现可答组最低 0.35、不可答组最高 0.39，区间是重叠的——因为"加拿大清关要什么资料"确实命中了关税文档，只是答案不在里面。所以我加了一层可答性门禁：问题里的实体如果从没在证据里出现过，就拒答。最终拒答正确率 0.92。
>
> 工程上做了鉴权、限流、幂等、熔断降级、Trace 和指标。145 条测试全绿，离线单请求 p50 8.9 毫秒。并发压测时 p95 到了 200 毫秒，我定位到瓶颈是 SQLite 同步写而不是检索，扩容路径写在架构文档里。
>
> 需要说明的是，默认用的是离线确定性模型，保证任何人 clone 下来不用密钥就能跑；质量结论要切真实模型重测，这一点我在评测文档里写明了。

## 6. 高频追问与答法

**Q1：为什么不用向量数据库？**
> 语料只有 24 个知识块。引入 Chroma/FAISS 会带来进程模型、持久化目录、版本兼容三类成本，而在这个规模下收益接近零。所以我自己写了 BM25 和特征哈希向量，索引常驻内存、可序列化，融合分数字段在响应里可见，便于调试。规模到十万块我会换真 embedding + 向量库，切换点写在 ADR-002。

**Q2：引用怎么防止模型编造来源？**
> 模型根本没有写来源的权限，它只能选编号。抽取编号后用 source_map 回填元数据，越界编号会被剔除并记 warning。进一步的，如果答案一个引用都没有，我直接判为不可验证并拒答——因为无法区分"没写引用"和"编的"。

**Q3：拒答率 0.92 是怎么算的？**
> 26 条评测集，20 条可答 + 6 条不可答。判据是 `no_answer == (not answerable)`，误答和误拒同权。现在是 24/26，两条漏网的是"加拿大清关"和"加密货币付款"，因为主题命中了相近文档、词面覆盖也够高，词面门禁识别不出来，需要 NLI judge。这在评测报告里单列了。

**Q4：为什么 HITL 不用 LangGraph 的 interrupt？**
> interrupt 需要 checkpointer，而且进程重启后的恢复语义比较复杂。我改成两阶段状态机：需要审批时把完整状态快照写库然后返回，审批时读快照只执行 finalize，不重跑检索和生成。好处是重启不丢任务、审批可审计、不重复计费，坏处是图被拆成两个入口，多步审批要加字段。

**Q5：145 条测试怎么分布的？**
> 12 个文件，全部离线，跑一遍不到 2 秒，行覆盖率 92%。分四层：纯逻辑（分块、BM25、引用、门禁、配置、指标、限流）；组件（检索命中、流水线引用、语料与索引持久化、工具与目录）；编排（意图路由、HITL 暂停恢复、轮次上限）；HTTP（401/422/409/429、幂等重放、租户隔离、SSE 事件序列）。另外专门测了模型供应商这条路：用 httpx MockTransport 覆盖 5xx 重试、429、超时映射、非重试 4xx、熔断打开后不再打主模型、降级到离线模型。

**Q6：8.9 毫秒和 117 rps 是怎么测的？**
> ASGITransport 进程内调用，不含网络栈，这样测出来的是自己代码的成本。单请求 p50 8.9 毫秒，其中检索 1.9 毫秒、图 6 毫秒。20 并发 300 请求是 116.7 rps、p95 213 毫秒、0 错误。并发下降主要来自每次请求 5 次 SQLite 提交。

**Q7：QPS 涨十倍怎么办？**
> 按性价比排：先把任务、审计、记忆的写合并成一次提交或走队列，预计 3-5 倍；然后 SQLite 换 Postgres，这样能多副本；限流和幂等键迁到 Redis；检索是无状态的，直接水平扩。都不需要改业务代码，接口都在 Store 和 Limiter 里。

**Q8：语料更新了怎么办？**
> 现在索引启动时重建，评测集和报告都带语料版本。真要上线我会加三件事：文档级 upsert、索引版本号进缓存键、评测门禁在 CI 里拦住"更新后指标下降"的提交。

**Q9：RAG 效果怎么评估才可信？**
> 分两层：检索层看 hit@k 和 MRR，跟生成无关；生成层看引用准确率、忠实度和要点覆盖。忠实度我用字符 3-gram 覆盖而不是让模型打分，因为规则版可复现。但要强调，离线模式的生成器是夹具，忠实度 0.997 是照抄引用的结构性结果，不代表模型质量——真实结论必须切在线模型重跑。

**Q10：这个项目最难的地方？**
> 不是写代码，是承认"阈值拍脑袋不对"。第一版我直接用了 0.2，结果 26 条里有一条可答问题被误拒。然后我写脚本打印分布，发现两组区间重叠，才意识到单阈值解决不了，必须再加一个信号。这个过程和数据我留在评测文档里了。

**Q11：如果重做一遍会改什么？**
> 三点：第一，可答性判定直接上 NLI 或 LLM judge，不要用词面代理；第二，写路径一开始就异步，不要等压测暴露；第三，离线夹具应该只用于单测，`make demo` 用真模型的小样本，避免"看演示很惊艳、跑评测很打脸"。

**Q12：哪些是你自己写的？**
> 框架和模式是公开的，代码是我写的。前期做过一个 9 天的实训项目，积累了这个业务领域的语料和政策知识；这个平台是重新设计的单仓工程，从目录结构、错误体系、编排到评测脚本都是重写。（**诚实回答，不要含糊。**）

## 7. 不能说的话（红线）

| 不要说 | 因为 |
|---|---|
| "支撑了 xx 万用户 / 日均 xx 万请求" | 没有线上流量，一问就穿 |
| "准确率 99%" | 你的口径是拒绝率与引用准确率，不是端到端准确率 |
| "用了 GPT-4 微调" | 项目里没有微调，只有提示词 + RAG |
| "基于公司真实订单数据" | 语料是虚构示例 |
| "完全防住了提示注入" | 只是启发式规则，报告里写明不是安全边界 |
